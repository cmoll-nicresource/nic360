# Independent recovery infrastructure change set

Prepared October 16, 2026, before activation. Account `226541720866`, region `us-east-1`, Railway beta only.

1. Create GitHub OIDC trust and `nic360-github-recovery`. Its [trust](../ops/backups/recovery-trust.json) accepts only `cmoll-nicresource/nic360` on `master`. Its [permissions](../ops/backups/recovery-policy.json) read three backup prefixes, write only verification evidence, emit the `Nic360/Recovery` health metric and send SES alerts only from `noreply@nicotineresource.org` to `cmoll@nicotineresource.org`. No database/upload writes or backup deletion permissions. The baseline was generated from the SDK calls with IAM Policy Autopilot; optional wildcard/KMS/ACL/Object Lambda grants were removed and resources constrained.
2. Create PostgreSQL login `nic360_backup` with `pg_read_all_data`, default read-only transactions and a five-minute statement timeout. Transfer its random password directly into a new Railway `database-backups` service, using the existing private database host. No inbound/public endpoint. No existing user's credentials change.
3. Create IAM user `nic360-database-backup-writer` with the [database-prefix policy](../ops/backups/database-writer-policy.json). Transfer its key directly into that service; never commit it or write a local credential file. Configure the reviewed [backup worker](../ops/backups/Dockerfile) daily at 07:00 UTC. It runs briefly and exits. Existing native snapshots and upload backup schedules remain configured.
4. Add lifecycle rules only for the new `database-daily/` (45 days) and `verification/` (90 days) prefixes. Preserve the existing bucket rules for uploads and historical rehearsals. These rules deliberately expire old backups, so the retention window is part of this approval.
5. Create a rotating customer-managed KMS key, `nic360-backup-alerts` SNS topic, and the [six-hour heartbeat alarm](../ops/backups/backup-alarm.json). [Key](../ops/backups/alert-key-policy.json) and [topic](../ops/backups/alert-topic-policy.json) permissions constrain the CloudWatch publisher to this account and exact alarm. Subscribe only `cmoll@nicotineresource.org`; AWS sends an email confirmation link that the recipient must click. Missing heartbeat counts as failure; CloudWatch's extra lookback can delay missing-data detection.
6. Enable the [GitHub recovery workflow](../.github/workflows/recovery.yml) only after provisioning. Six-hour freshness checks and Sunday/manual network-disabled full restores run outside the app. Recovery downloads stay in private ephemeral runner storage and are removed; no customer data becomes a GitHub artifact. Controlled alert and test publication emails go only to the already approved staff inbox.

This adds a brief daily Railway job, bounded database archive storage, a CloudWatch custom metric/alarm and a KMS key. It does not change live Stripe mode, reader email safe mode, DNS, current application data or current backup destinations. The synthetic worker and restore test pass locally and run in regular CI. Real recovery remains strict about the ten documented pre-existing missing prototype files; those are not silently exempted.
